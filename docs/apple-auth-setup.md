# Sign in with Apple — owner setup

The application uses Supabase Auth OAuth with its existing PKCE callback. The Apple button is off by default: `APPLE_AUTH_ENABLED=false`. Do not turn it on until the real provider and redirect configuration are complete. This flag is server-side; it is not an Apple secret.

1. In the Apple Developer account, register an App ID with the Sign in with Apple capability and create a Services ID for the website. Configure the Services ID's web domain as `kafahjtiyrfpruqvnryh.supabase.co`, and its Return URL as `https://kafahjtiyrfpruqvnryh.supabase.co/auth/v1/callback`. Verify the production `NEXT_PUBLIC_SUPABASE_URL` points to that same project before registration. This is the provider return URL, **not** the NIS Hub app callback.
2. Create a Sign in with Apple private key (`.p8`) for that Services ID. Keep the private key, Key ID, Team ID and generated client secret in the Apple Developer account and Supabase Auth provider configuration only. Never put them in this repository, browser code, `NEXT_PUBLIC_*`, or chat.
3. In Supabase Dashboard → Authentication → Providers → Apple, enable the provider and enter the Apple Services ID (client ID) and the current client secret generated from the Apple key. Follow Supabase's current Apple setup guide for the exact Dashboard fields. Apple web OAuth client secrets need renewal at least every six months; record an owner reminder before expiration.
4. In Supabase Dashboard → Authentication → URL Configuration, keep the stable Site URL `https://nis-hub-ura.vercel.app` and allow `https://nis-hub-ura.vercel.app/auth/callback` in Redirect URLs. The app sends this **application** callback as `redirectTo`; Supabase exchanges Apple's response at its own `/auth/v1/callback` first.
5. In Vercel Production environment, set `NEXT_PUBLIC_SITE_URL=https://nis-hub-ura.vercel.app` if not already present and set `APPLE_AUTH_ENABLED=true` only after steps 1–4. Redeploy Production. Keep previews disabled for Apple OAuth: PKCE verifier cookies are bound to the origin that started login, so the server redirects previews to the canonical Production origin before initiating OAuth.
6. Test in a private browser window on the canonical Production URL: new Apple account, returning Apple account, cancelled/expired login, and an existing password or Google account whose **verified email** matches an Apple identity. Verify one profile is preserved with its class, Top 4, role and saved data. Also test Apple's private-relay email: a relay address may not equal an existing email and automatic identity linking is not guaranteed. Do not force-link by unverified email or provider metadata.

The NIS Hub profile trigger creates a student profile once and never promotes a role or overwrites profile settings from Apple metadata. Apple web OAuth does not provide a reliable full name. If there is no display name, the existing profile-edit flow remains the source of truth. Email/password and Google remain available independently of this feature flag.

The button uses Apple's official sign-in logo artwork in accordance with its artwork license and Human Interface Guidelines. The owner must ensure its Apple Developer membership and usage meet Apple's license terms before enabling this on a public deployment.

References: [Supabase Sign in with Apple](https://supabase.com/docs/guides/auth/social-login/auth-apple), [Apple Sign in with Apple design guidance](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple).
