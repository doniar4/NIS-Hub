## Changes

### Schedule and administration

Canonical subject Maps replace render-loop lookups; the shared subjectName helper retains RU/KZ/EN fallback. Classes sort naturally by grade/section. Room normalization preserves named locations.

An additive non-school calendar drives local Home arrows and full Schedule. Every skipped weekend/vacation/cancellation interval includes dates/reasons, including overlaps. Today-off and preview states remain distinct. Existing canonical timetable→Library subject/class links and normal empty states are preserved; teachers remain in storage/import/admin preview but not student rows.

Every committed bulk import, lesson deletion and restore records a complete snapshot. Baseline retains the existing timetable. Historical and prospective-restore diffs show added/removed lessons and subject/time/room/block changes; room replacements are emphasized. Restores are explicit, atomic, serialized, audited and protected against stale active-version confirmation.

Admin now has dedicated books, timetable/import, versions, non-school days, catalog and ticket sections, counts and recent imports.

### Tickets and Telegram

Private owner/admin ticket RLS, bounded authenticated RPCs/actions, six categories, four statuses, replies, status audit history and database-enforced per-account rate limits. Clients cannot forge owner/author/role/status or directly mutate ticket tables. Existing admins moderate; no extra role.

Supabase persistence precedes Telegram. Telegram forwards a Russian heading/category, title, preview ≤400 Unicode code points including …, optional safe profile display name, Asia/Oral timestamp and canonical ticket link. No full long body, replies, account email or auth metadata is forwarded. Dynamic HTML is escaped; obvious URLs/emails/credential patterns are redacted as best-effort minimization, not guaranteed anonymization. Five-second delivery timeout, no redirects/link previews, fixed-code safe logs, and notification failure never rolls back creation. Optional profile-name lookup has a separate 1.5-second limit after persistence and fails to an omitted name. The existing shared ticket detail route renders admin controls; there is no separate admin detail route.

All three legal drafts and the RU/KZ/EN ticket form notice describe title/preview/name forwarding and its limits, alongside actual deletion/retention behavior; the legal texts remain Draft/not legal advice.

### Experience

Original sprout/botanical/subject SVGs, ivory/sage and deep-green themes, collapsible fixed desktop sidebar, accessible modal mobile drawer, functional Library search, full language names and header avatar.

Home has localized formal greeting/tagline, timetable and Continue Reading cards. Actual optional private covers render via signed URLs; absent/unavailable images use typography, not invented art. Library/Profile/Schedule styling aligns with the shell.

Accessible Light/Dark/System radio segments have restrained liquid movement. Reduced motion disables animations. Intro runs only on full document load/reload, ends within 900 ms, adds no data delay and does not replay on filters/tabs/client navigation.

Phase 4 Reader, signed PDF route, publishing and private-upload implementation were not rewritten.

## Known limitations

- One Chromium Phase 4 browser run reported PDF.js ReadableStream enqueue/close errors after the functional Reader assertions succeeded. Two subsequent unmodified Chromium/WebKit runs passed with the page-error assertion intact. The cause was not isolated; neither Reader code nor error collection was changed. Rapid page/zoom/reload behavior remains a real-session verification item.
- Telegram is one best-effort attempt: no retry queue/webhook/delivery guarantee. Admins must also check the dashboard.
- Awaiting-reply is not a per-admin read receipt. No attachments, moderator role, priorities, self-service deletion or automated retention job.
- Weekends always skip; no make-up Saturday model. Holidays require school configuration. Search is bounded to 366 candidate days; free-text reasons are not auto-translated.
- Full Schedule retains its current Monday–Friday window; Home previews nearby school days. Calendar exceptions are separate from version restoration.
- Full snapshots are bounded to 10,000 lessons; history growth requires operator planning. Removed historical FK references cause safe restore failure. Out-of-band database-owner SQL is not an audited application workflow.
- Real covers require authorized operator upload/cover_path administration; no new cover editor. Existing explicit Library 5,000-book bound and 200-book admin list remain.
- Privacy/Terms still require operator/contact/hosting/retention/effective-date decisions and legal review.
- No EduPage scraping, new external schedule integration, analytics, advertising, payments or unrelated features.
