## Calendar and school-day navigation

Admin → Non-school Days: enter inclusive ISO dates, type and a meaningful reason. Overlaps retain all applicable reasons. The maximum interval has end minus start ≤366 days (367 inclusive dates). Up to 5,000 exceptions load in bounded 500-row pages; exceeding the limit fails explicitly.

Saturday/Sunday always count as off. Holidays and vacations must be configured by the school, not inferred from a national calendar. Free-text reasons remain as entered; provide multilingual wording if necessary. Type/date labels are localized.

Home arrows search up to 366 candidate dates for the previous/next calendar school day, skipping weekends and configured exceptions. Every skipped interval is shown with its full reasons and range. “Show nearest school day” means the next upcoming school day. Preview dates are explicitly distinguished from Today. A valid school day with no imported lessons shows the normal empty state.

Full Schedule retains its current Monday–Friday window and local class/day filtering, suppressing regular lessons on exceptions. No per-arrow/filter requests. Dates use Asia/Oral. Subject links retain canonical subject/class Library filters. Teacher remains in the data/import/admin preview, not student timetables.

## Import versions and safe restore

CSV/TSV parsing, bounded sizes, overlap checks, accepted names and upsert semantics remain as documented in Phase 4. Numeric classroom labels normalize; named locations stay intact. Omitted rows are not implicitly deleted.

Every successful import creates an immutable complete timetable snapshot, up to the existing 10,000-row timetable bound. Identical imports preserve lesson IDs/timestamps but still record a batch. Explicit lesson deletion creates a version too. History lists 100 batches per page; selected/previous/active snapshots load separately.

Admin → Schedule Versions:

1. Select a historical version and inspect its changes from the previous active version.
2. Inspect the separate prospective diff against the **current** active version.
3. Confirm the warning: restoration replaces the entire weekly timetable, not one class.
4. Restore. A new audit batch records actor, previous version and restored-from version.
5. If another admin changed the active version meanwhile, reload, compare and confirm again; stale restoration is rejected.

Imports/deletes/restores serialize under a transaction lock. Validation, missing FK or exclusion errors roll back both data and audit changes. If a historical class/subject was later removed, restore fails safely until the reference is restored through an authorized process. History is never erased by the application. Restoring a weekly snapshot does not undo calendar exceptions.

## Support and retention

Only the existing admin role moderates tickets. Authors view their own tickets/replies and reply while open/in progress. Administrators list/filter, reply and change status. Status changes are audited. Direct API ticket DML is denied; bounded RPCs validate authority and ownership.

“Awaiting administrator reply” means the last message is from the author, not a per-admin read receipt. Limits: one ticket/minute, twenty/day; one reply/five seconds, sixty/hour per account.

Telegram receives the Russian heading/category, title, message preview ≤400 Unicode code points including …, optional safe profile display name, Asia/Oral timestamp and ticket link after persistence. Long descriptions and replies are not forwarded; short messages may fit in the preview. Account email, attachments and auth data are not included. Dynamic HTML is escaped and obvious URLs/emails/secrets are redacted; free-text minimization is best effort, not guaranteed anonymization. The existing `/support/<id>` detail route renders admin controls by authenticated role; no separate admin detail route exists. See Telegram setup for boundaries and manual tests. One five-second, no-redirect attempt; no outbox/retry or delivery guarantee. Admins must check the dashboard.

No self-service deletion or automatic retention job is added. Verified operator deletion of an account cascades its tickets/replies/status history in the database. Telegram messages, provider logs and backups require separate handling. Fill the legal drafts' operator/contact/hosting/retention/effective-date fields before public launch.

## Optional real covers and avatars

book-files stays private and PDF-only, with its unchanged 50 MiB cap. The separate private book-covers bucket accepts WebP/PNG/JPEG ≤2 MiB. Only admins upload; authenticated readers access only covers referenced by published books.

There is no new cover-upload editor. An authorized operator may upload an actual permitted image through Supabase Storage at `books/<book-id>.webp` (or .png/.jpg/.jpeg), then set the book's existing cover_path to that relative path through authorized metadata administration. Do not use external/public URLs. Nothing is automatically uploaded or published.

Continue Reading signs real covers for 60 seconds; missing/invalid/failed images get a typographic placeholder. Reload obtains a fresh URL. No invented textbook art is used.

Avatars retain `<uid>/avatar.webp`, WebP ≤256 KiB and the 60-second replacement cooldown. The header signs the current user's canonical avatar anew on server render. An image error shows initials/Profile link; Profile retains its retry behavior.
